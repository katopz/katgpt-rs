# katgpt-rs targets that are LOAD-BEARING BY NAME and in which EVERY test is
# unconditionally `#[ignore]`d — so the binary compiles, runs, and can never
# print anything but `ok. 0 passed`.
#
# MEMBERSHIP, not a count, and that distinction is the whole point
# --------------------------------------------------------------
# `cfg_gated_floors.txt` argues — correctly — that the COUNT of ALL-IGNORED
# targets is not gateable, because `#[ignore]` is the right marker for a slow
# or hardware-gated test. What that argument does not reach is that a count is
# not a checksum over a set: one justified row leaving while one unjustified
# row arrives keeps the total unmoved. That is not hypothetical here. The pins
# file header recorded "19 ALL-IGNORED (3 load-bearing)" and the measurement
# on 2026-09-03 evening was **5** — the count grew by two and nothing noticed,
# because no pin existed on it at all. (The two arrivals are the `*_uq_floor`
# rows below; they became load-bearing when Issue 713 T4c widened the
# `is_load_bearing` token set to the `floor` dialect. A vocabulary widening
# that finds two more targets is the instrument WORKING — what was missing was
# anything that said so.)
#
# So this file is the allowlist. Every row is a judgement call its owner has
# already made and this gate accepts; what it refuses is a SIXTH row arriving
# unannounced, before its green `ok. 0 passed` is cited as evidence for a
# promotion.
#
# It is also self-protecting against blindness, which a ceiling of zero never
# is: if the auditor's `#[test]` or `#[ignore]` recogniser regresses, the
# measured set empties and the gate reds on five REMOVALS. A count ceiling
# would have passed.
#
# Re-pin DELIBERATELY, in the commit that changes the set, with the reason in
# the commit message — and drift in EITHER direction reds. A removal is good
# news (somebody un-ignored a load-bearing gate) and still needs the pin
# updated, exactly as `scripts/repo_set.txt` treats an arriving repo.
#
# Every reason below was read out of the file's own `#[ignore = "..."]` string
# on 2026-09-03, not inferred from the filename.
