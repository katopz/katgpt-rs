# Pins for scripts/pipefail_discard_drift_sweep.py — EVERY contract repo.
#
# Format, 5 whitespace-separated fields:
#
#   <repo> <min_sh_files> <min_sites> <max_findings> <max_unparsed>
#
# Re-pin DELIBERATELY, in the commit that changes the measured value, with
# the reason in the commit message. A pin that drifts behind reality is a
# pin nobody trusts.
#
# ── the two FLOORS ────────────────────────────────────────────────────────────
# max_findings is green over whatever the classifier can SEE, and the walk
# shells out to `git ls-files` — a regression takes the population to 0 and
# every ceiling passes, indistinguishable from a clean repo. So the
# population is pinned underneath, in two independent quantities:
# min_sh_files moves when the WALK goes blind, min_sites when the CLASSIFIER
# goes blind on an unchanged tree.
#
# Both are ~60% of the measured value: SLACK against churn (consolidating
# ad-hoc scripts legitimately shrinks the count by a third, and a floor
# that ratcheted to the last measurement would red that refactor and teach
# whoever hit it that the sweep is noise), TIGHT against blindness (a walk
# regression drops these by an order of magnitude, not by a third).
#
# ⛔ Exceptions are measured, not rounded: riir-esp32's min_sites is 0
# because the repo measures ONE site — any floor above 0 would red on
# adding a second site and teach the wrong lesson. katgpt-web has no
# tracked .sh at all: both its floors are 0 and detect nothing; its
# ceiling still reds the day a script lands there unmeasured.
#
# ── max_findings is EXACT, not slack ─────────────────────────────────────────
# Every finding is pinned by MEMBERSHIP in pipefail_discard_expected.txt
# (one reason per row, reds in both directions), so the ceiling adds only
# one thing: a wall at the pinned count. Set it to the measured pinned
# count, never above — a ceiling above the pin count would admit an
# unpinned finding's ARRIVAL as long as something else was fixed first,
# which membership then has to catch alone.
#
