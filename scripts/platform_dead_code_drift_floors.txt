# Pins for scripts/platform_dead_code_drift_sweep.py — EVERY contract repo.
#
# Format, 5 whitespace-separated fields:
#
#   <repo> <min_rs_files> <min_candidate_decls> <max_findings> <max_modref>
#
# Re-pin DELIBERATELY, in the commit that changes the measured value, with the
# reason in the commit message. A pin that drifts behind reality is a pin
# nobody trusts.
#
# ── the ceilings are a WALL, not a ratchet ────────────────────────────────────
# max_findings = 0 in every repo, and that zero was EARNED the week this
# instrument landed: the first sweep it ever ran found two live rows in riir-ai
# — `note_ane_dispatch` (declared ungated in an `ane_prefill`-gated module, all
# three call sites `all(target_os = "macos", target_arch = "aarch64")`) and
# `gen_u64_bytes` (used only from a `target_pointer_width = "64"` arm, and this
# workspace builds wasm32). BOTH reproduced as rustc warnings before being
# touched; repaired riir-ai `7b97ab97e`.
#
# ⛔ Do not "fix" a red by raising a ceiling. A new row is an item that is dead
# code on every platform but one, and NO automatic lane in this workspace
# compiles the platform that would say so — full_gate is macOS/aarch64,
# wasm32_gate is wasm32, and the x86_64-native lane that emits the warning is a
# workstation lane. The repair is one attribute: give the declaration the same
# cfg its uses already carry.
#
# max_modref is the second ceiling and is 0 everywhere but katgpt-rs. A MOD-REF
# row is NOT a rustc finding (a module whose own items are each gated is EMPTY
# on the other platform, not dead — measured on katgpt-types::simd::horizontal,
# where a wasm32 `cargo check` is silent and appending one ungated `fn`
# reproduces the warning on the **fn**). It is still a row somebody should read
# once, so it is walled rather than ignored.
#
# ⚠ katgpt-rs's 1 is a COUNT here and a MEMBERSHIP pin in
# `platform_dead_code_floors.txt`, which is the file that actually holds it —
# a count of 1 stays 1 when that row is repaired and a different, unread module
# takes its place. The sweep ASSERTS the two agree rather than trusting them
# (the docs_gate_paths_sync idiom: same quantity, two files).
#
# ── the two FLOORS, and the second is the one that bites ──────────────────────
# A ceiling of 0 is green over whatever the classifier can SEE, and this one has
# two independent ways to go blind:
#
#   min_rs_files          the WALK. `list_rs_files` shells out to `git ls-files`
#                         and falls back to an rglob; a regression takes the
#                         population to 0 and every ceiling passes,
#                         indistinguishable from a clean repo.
#   min_candidate_decls   the PARSE. The walk is intact and the token pass
#                         yields nothing — measured three times while the
#                         classifier was being built (an `any(...)` recursion, a
#                         swallowed closing paren, an unhandled `'`), each of
#                         which produced a confident `0 findings` over a full
#                         walk. ONLY this floor moves when that happens.
#
# Both sit at ~55-60% of measured: SLACK against churn (removing a crate
# legitimately shrinks both, and a floor that ratcheted to the last measurement
# would red that cleanup and teach whoever hit it that the sweep is noise),
# TIGHT against blindness (a walk or token regression drops these by an order of
# magnitude, not by a third).
#
# ── no MOD-REF membership pin per repo, deliberately ──────────────────────────

# where the gate pins it by name. Adding a name column here would duplicate that
