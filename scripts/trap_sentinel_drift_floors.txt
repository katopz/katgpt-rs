# Re-pin DELIBERATELY, in the commit that changes the measured value, with the

# ── the ceilings are a WALL, not a ratchet ────────────────────────────────────
# There is exactly ONE standing finding in the workspace and it is pinned
# below with its reason. Every other class is 0 in all 17 repos (2026-09-07),

# across ten repos and 37 scripts in one day. Nothing outside katgpt-rs was
# holding it. Now something does.
#
# ⛔ Do not "fix" a red by raising a ceiling. A new EXPOSED row means a gate
# script can report a PASS on an abort — the repair is one line (see
# scripts/full_gate.sh's full_gate_cleanup), and Issue 734's whole provenance
# is that nobody objected at the time.
#
# ── the two FLOORS ────────────────────────────────────────────────────────────
# max_exposed = 0 is green over whatever the classifier can SEE. `walk_sh`
# shells out to `git ls-files`, so a regression there takes the population to 0
# and every ceiling passes, indistinguishable from a clean repo.
#
# min_population catches that where a population exists. It CANNOT do the job
# alone: six of the seventeen repos have a population of ZERO (no script with
# both an abort-on-error option and an EXIT trap), so their floor is 0 and
# detects nothing — min_scripts, the size of the tracked-*.sh walk, still bites
# there and is the quantity a git ls-files regression actually moves.
#
# Both are ~60% of measured: SLACK against churn (consolidating three ad-hoc
# gate scripts into one legitimately shrinks the count by a third, and a floor
# that ratcheted to the last measurement would red that refactor and teach
# whoever hit it that the sweep is noise), TIGHT against blindness (a walk
# regression drops these by an order of magnitude, not by a third).
#
# katgpt-rs's min_population is NOT free: it must equal
# trap_sentinel_gate.POPULATION_FLOOR, and the sweep asserts that rather than
# trusting it — same quantity, two files.
#
# ── no membership pin here, deliberately ──────────────────────────────────────
