# katgpt-rs ONLY, and deliberately so. docs_gate.yml runs on ubuntu-latest with
# a single checkout; the siblings are private and simply are not there. A
# cross-repo version of this gate would derive an empty population and print a
# confident green over zero repos, which is the same defect the whole issue is
# about. That is also why scripts/docs_drift_sweep.py is excluded from
# docs_gate.sh's CHECKS. Sibling coverage is Issue 713 T3, an owner call in
# each owning repo, and the workstation instrument for it is
# `scripts/cfg_gated_target_audit.py` with no arguments.
#
# Format:  <key>  <value>
#
# The pins are two-sided ON PURPOSE
# ---------------------------------
# (The COUNT is deliberately not written here. This header said "FOUR" while
# the file carried six, and then eight — the same drift the docs gate exists to
# catch, committed by the header describing the gate. `REQUIRED_PINS` in
# cfg_gated_floor_gate.py is the list; it is derived from this file's keys and
# fails on a missing one.)
# A ceiling alone is a gate that cannot fail once the instrument dies: an
# auditor whose regex stops recognising `#![cfg(...)]` reports SILENT-NOW 0,
# which passes every ceiling ever written. So two of the four pins are FLOORS
# on the population the auditor claims to have looked at. This is Issue 705's
# lesson (the full gate's first two CI runs passed over ZERO compiled units)
# applied before it happens rather than after.
#
#   max_load_bearing   the sharp one. Targets whose filename says their green
#                      IS the evidence for a promotion (goat / gate / g<N> /
#                      drill / proof / invariant / guard / conservation /
#                      safety / security / audit). T2 armed all 39 of
#                      katgpt-rs's, so the correct value is 0 and any new
#                      unarmed one reds per-push. This is the pin worth having.
#   max_silent_now     the ratchet. Every remaining default-off gated target
#                      with no required-features row. Exact, not slack: the fix
#                      is a three-line Cargo.toml row that the report prints
#                      verbatim, and slack in a ratchet is just a slower
#                      version of no ratchet. Arming more targets lowers the
#                      real count; the gate then says so and asks to be
#                      re-pinned, it does NOT fail.
#   min_targets        blindness floor. Generous by design — it exists to catch
#   min_gated          "the auditor stopped seeing anything", not to police
#                      churn. Pinning the exact observed count here would red
#                      on every legitimate test-file removal and then be
#                      ignored, which docs_drift_floors.txt's header already
#                      argues at length. Set at roughly 75% of observed.
#
#   max_reasonless_ignores   Issue 713 T6's SECOND axis, and the one pin that
#                            axis defensibly supports. A target where EVERY test
#                            is #[ignore]d prints `ok. 0 passed` forever, which
#                            is legitimate for a slow or hardware-gated test —
#                            so the COUNT is not gateable. What is gateable is
#                            that the source SAYS WHY: an `#[ignore]` with no
#                            reason string leaves no reader able to tell a
#                            deliberate manual-only test from one parked during
#                            a refactor and forgotten. 27 such ignores across 8
#                            targets were given their file's OWN documented
#                            reason on 2026-09-03; the reason now appears in
#                            cargo's output, where the reader actually is.
#   min_ignore_targets       the matching blindness floor. Same argument as
#                            min_targets: the reasonless pin is a ceiling of
#                            zero, and a parser that stops recognising
#                            `#[test]` satisfies it perfectly.
#
# Observed 2026-09-03 (second measurement, same day): 921 targets, 541 gated,
# 395 covered, 44 SILENT-NOW, 0 load-bearing SILENT-NOW, 100 latent, 2 platform
# (0 positive), 1 any(); 653 ignore-scanned targets, 460 with tests, 19
# ALL-IGNORED (3 load-bearing), 0 reasonless.
#
# That "(3 load-bearing)" was measured **5** the same evening and this line did
# not move, because NO PIN EXISTED ON IT. The two arrivals are the
# `*_uq_floor` targets, which became load-bearing when T4c widened the
# `is_load_bearing` token set to the `floor` dialect — the instrument working,
# with nothing to say so. Closed by MEMBERSHIP rather than by a count:
# `scripts/all_ignored_load_bearing.txt` lists the five paths and
# `check_membership` reds on drift in either direction. The header's own
# argument that "the COUNT is not gateable" was right and incomplete — a set
# is gateable where its cardinality is not, which is also why an empty
# allowlist is REFUSED instead of read as a ceiling of zero. That pin is not
# in REQUIRED_PINS below: it is not an integer.
#
# The first measurement of the day read 376 covered / 63 SILENT-NOW, and the
# delta is NOT churn: `max_load_bearing = 0` was a green over a population the
# CLASSIFIER COULD NOT SEE. Widening its token set to the alloc / correctness /
# determinism / equivalence / floor / grad dialect (measured against all 2,157
# workspace test+bench targets first) surfaced 17 more load-bearing katgpt-rs
# targets — 8 `*_alloc_check` G4 budgets, 4 `*_backward_grad_check`, a
# Report-the-Floor UQ gate, a determinism gate, a checkpoint-equivalence gate,
# and two grad gates. All 17 were armed and then RUN in release: 45 assertions,
# 45 pass, 0 fail. Same finding as `.issues/714` T3 — they were silently
# UNVERIFIED, not silently broken, which is exactly why nobody noticed.
#
# The lesson for anyone tempted to trust a zero: a ceiling of zero over a
# classifier is only as wide as the classifier's vocabulary, and a vocabulary
# gap looks identical to a clean repo.

# The PROFILE dimension (riir-ai `.issues/855` Class 2, added 2026-09-03). TWO
# pins because the directions are opposite in severity — pooling them would
# repeat the error the report itself documents for positive-vs-negated platform
# gates, one axis over.
#
#   max_profile_release_only  the sharp one. `#![cfg(..., not(debug_assertions))]`
#                             compiles to an EMPTY binary under plain
#                             `cargo test` — the DEFAULT invocation, on the
#                             right machine, with no flags typed. Every other
#                             predicate in this report needs somebody to have
#                             CHOSEN the silent configuration. And unlike
#                             SILENT-NOW there is no fix to apply: cargo has no
#                             profile predicate in `required-features`, so a
#                             row moves the target into the "covered" column
#                             while changing nothing. katgpt-rs has ZERO today,
#                             so the correct value is 0. A release-only bench
#                             is legitimate — raise the pin and say WHY.
#   max_profile_debug_only    the ratchet. `#![cfg(..., debug_assertions)]`
#                             vanishes under `--release`, the profile AGENTS.md
#                             tells everyone to run gates in. katgpt-rs has
#                             exactly ONE: tests/kimi_k3_g4_alloc_free.rs,
#                             load-bearing, and CORRECT — the alloc counters
#                             are debug-only by design and that file asserts
#                             nothing else. What would not be correct is the
#                             same file also carrying a wall-clock budget: no
#                             single profile can observe both. riir-ai
#                             `.issues/855` Class 3 is the worked split (an
#                             alloc+timing G4 measuring 3 ms/cycle in debug
#                             against 14.35 us in release — a 209x artefact on
#                             a bar the code clears by 70x).
#
# Workspace context, for whoever raises these: 133 profile-gated targets over
