## TL;DR

A four-part **graft** adds a deterministic skill (arithmetic) to SmolLM2-135M with no gradient training and ≤0.09% added weights: **read** (least-squares linear probes pulling operand digits from hidden states — layers 14+20+21 joined read all six digits at 97.9% on fresh problems), **rules** (per-answer-digit lookup tables, hand-wired or mined by a program that searches for the *smallest set of input digits that decides each answer digit* and reuses found rules — the tens digit is the units rule reused plus a carry step: **one rule serves many facts**), **write** (a per-digit-place-scaled push toward the right token at the last layer — the model still writes its own reply), **switches** (two fitted gates keeping the graft on only while the model writes this problem class's answer; off on other math, word problems, code, plain text). All fitting is closed-form least squares; base weights untouched; grafts are sidecars. Held-out gains: multiplication +61.8, subtraction +57.1, 2-digit addition +36.8, 3-digit addition +57.6 points; scrambled-wiring controls score at-or-below baseline; head-to-heads beat a tuned same-size gradient graft by ~58–60 points and LoRA (115k trained weights, 39.4%) by 49.3 points with a quarter of the weights (88.7%).

**Distilled for katgpt-rs (modelless, inference-time):**

The general primitive is not arithmetic — it is **`Graft { reads, rules, writes, switches }`**: a deterministically-fitted, digest-pinned sidecar overlay that (1) reads structured task state out of the model's own hidden states with closed-form linear probes, (2) computes the answer through a deterministic rule table (authored, or mined from a few hundred solved examples by minimal-deciding-set search), (3) writes the computed answer into the sampling distribution (logit bias at the last layer — NOT residual-stream surgery), (4) arms per input class through fitted sigmoid-style switches. This is the modelless doctrine ("raw/lora hot-swap — a **deterministically constructed** overlay", Plan 025) realized at the LM level with an explicit compute layer between read and write, and it gives the workspace its first *fitted-from-examples* overlay FAMILY — the closed-form fitting machinery itself already ships (`katgpt-attn-match` `beta_fitter`/`value_fitter`, §4); what does not ship is the graft pipeline that consumes it.

## 1. Paper Core Findings (their claims, their numbers)

1. **The digits are already in there.** A linear read of the hidden state at the answer position extracts operand digits almost perfectly; single-layer reads peak at 76.6% (layer 21) for 3-digit addition, and joining layers 14/20/21 reaches 97.9% (99.2% at 3k fit problems). The last layer alone is worst (11.8%). The model reads the question; it cannot reliably *combine* — the graft supplies combining.
2. **Four parts, none trained by gradient descent** — read (LS probes), rules (lookup tables per answer digit; units digit from the two units digits, tens from tens + carry, etc.), write (scaled push at the last layer), switches (two fitted on/off gates). The base model file is never touched.
3. **The rule miner** gets 340 solved problems as digits+answers; per answer digit it finds the smallest input set that decides it, keeps a rule only if it holds on every example, and reuses prior rules upward (units rule reused on tens + a carry signal nobody named — the program found the variable because the data needed one). Digit factorization was "the most important choice": 7 × 48 = 336 is one fact among 720 whole-problem states, but split into digits, the answer's last digit depends only on {7, 8} — a ~100-entry table that 340 examples fill almost completely.
4. **Simplicity beats gradient under few examples.** Same-size gradient graft: 72.7% on its own training problems, 25.1% on dev (memorization); circuit: 94.7% built-from, 88.7% dev. On sealed held-out: circuit 83.5% vs gradient graft 25.6% (14 neurons) / 23.7% (77 neurons, tuned); LoRA 115,200 trained weights: 39.4% vs graft 88.7% on dev. Subtraction: circuit 64.98% (untuned, settings copied) vs tuned 77-neuron gradient graft 65.0% — a tie at a quarter of the parameters.
5. **Five skills land with the same pipeline.** Program-found rules: multiplication 82.7%, subtraction 68.3%, addition-2d 86.5%, addition-3d 83.7% held-out; three-digit addition needed exactly three fixes (3-layer read join, second switch, per-place push strength) — each tested before its held-out set opened.
6. **Coexistence + controls.** The three two-digit grafts run together in one model (92,496 weights); worst change on other math −0.25 points; 200/200 unrelated prompts (IFEval, greedy) byte-same answers. Scrambled wiring scores 2.4–21.4% (at/below baseline): the weights do nothing without the rules.
7. **Open thread — transplants from bigger models:** translating Qwen3.5-4B neurons into SmolLM2 and mapping a correction signal into Qwen3.5-0.8B have both failed so far; the big model is most useful as a guide to where the small one breaks.

## 2. Distillation — the primitive under the arithmetic

- **Digit factorization is input-space structuring, not a math trick.** The enabling move is choosing a representation where one deterministic rule covers a whole equivalence class of inputs (all problems sharing a digit pair). The workspace analog: any task decomposable into a small state vector the model already holds linearly, where a fixed table over state-combinations decides the output. Selling point form: *"deterministic skill, O(1) table, ~0.02% parameters, zero training run."*
- **Minimal-deciding-set mining is textbook rule induction (OneR/CN2/RIPPER/DreamCoder-library lineage) — the novelty is the substrate it consumes.** The miner runs over *probe reads of hidden states* (derived per-input, cheap) rather than raw features, and its output compiles into a graft table. Rule reuse across digit places (units rule + carry) is DreamCoder-style library learning at table scale.
- **The switches are fitted sigmoid gates** — same fitting family as `SigmoidGateCalibrator` (closed-form 2-param Platt refit over recorded pairs). "On while writing this problem class's answer" is a position-conditioned gate; the paper fits it by least squares over position labels.
- **The write is sampling-distribution bias, not activation surgery.** This matters for us (§3 Fusion B): the entire intervention sits *outside* the forward pass proper — reads tap hidden states, writes touch next-token logits. PhraseBoost already ships sampling-time token biasing from a lookup structure (GOAT-promoted); TokenGate (riir-infer Plan 622) ships deterministic attention-key bias with a demote-only env. The write seam is precedented in-house; what's new is that the bias is *computed* from probe reads through a rule table.
- **The scramble control is the falsification arm we should steal.** Same weights, shuffled wiring, must land at/below baseline — a cheap, decisive guard against "the extra weights alone do the work" (the gradient-graft failure mode measured in their Table: tuned gradient grafts never cleared 26%).

## 3. Fusion — paper × workspace, what none of them alone has

**A. Graft × `npc_brain_graft` (riir-ai Plan 629/Proposal 055).** The authored predecessor already ships: whole-row ternary sign/scale overlays on a rootstock brain, mint-time composition, an exact-LP flip-attribution feasibility gate, and a **`ProbeSet`** — authored (observation → expected action) pairs that must hold for the graft to mint ("no probes → no mint"), plus a BLAKE3 LineageManifest sidecar, base weights untouched, "authored, not learned: no training". The graft pipeline is this shape's **fitted, LM-domain successor**: ProbeSet authored → probe reads least-squares-fitted from ~340 examples; LP feasibility gate → scramble control + fitted switches; ternary row tables → mined minimal-deciding tables. Cross-pollination BACK: the exact-LP flip-attribution check ("can row j overtake row i anywhere in the observation envelope?") is a stronger interference guarantee than the paper's empirical side-effect audit — a graft-composition gate worth carrying into any multi-graft LM stack (their three-graft coexistence was measured, not proven).

**B. Graft × FPCG (Plan 292, Research 267) — the constraint-compatible write seam.** FPCG ships sigmoid linear probes on the mid-layer residual stream under a hard constraint: *"Read-only at the LLM level … never modifies the residual stream — breaking this rule voids the GOAT gate."* The graft does NOT lift that constraint — FPCG stays read-only — it is a **separate primitive whose write target is the sampling distribution** (last-layer logit bias, PhraseBoost's precedent), with its own gate. Composition: FPCG selects *which* candidate (steer-via-selection), a graft computes *what* the answer digit must be (steer-via-computation); both consume probes, neither touches the residual stream.

**C. Graft × LoraPair/LoRAHotSwap (Plan 025, riir-ai hot_swap.rs).** The doctrine says overlays may be "deterministically constructed (not trained)". LoraPair instances today carry *trained* weights (plan 025 L19 caveat); the graft is the first fully-deterministic overlay *family* — probes + tables + switches all closed-form — that could mount through the same hot-swap registry as a `GraftSpec` sidecar (digest-pinned, monotonic apply, the freeze/thaw envelope law). The graft's fitted switches are the per-input-class arm/disarm that LoraPair's context-key switching approximates with hashes.

**D. The rule miner × riir-refine rulewright.** "Smallest set of inputs that decides the outcome, kept only if it holds on every example" is a *minimization objective* the rulewright's L0 distillation does not currently optimize (rules are mined per source with fixtures, ranked by Elo/Beta evidence). Recorded as cross-pollination only — no filing: the rulewright's rules are pattern→fix rows over text, not decision tables over derived features, and its corpus-scale evidence machinery is strictly richer.

**E. Graft lanes in the decision family (priority-ladder #1 check).** A deterministic skill overlay armed by fitted switches is a natural third lane beside modelless + encoder in the ESC ladder — `EscalateSpec` grammar, abstain-when-off maps exactly onto the switch-off posture. Honest consumer check: the current reflex suites are classification, not exact-answer arithmetic — **no serving consumer exists today**; this stays a recorded future surface, not a filed plan. The primitive lands engine-side first.

**F. riir-train negative-evidence note (no plan owed).** The paper's training-side items are all *negative evidence for the graft lane*: gradient grafts memorize at 340–1.5k examples (72.7/25.1 train/dev); LoRA needs 4.5× the parameters to land 49 points lower; the transplant thread fails the same way our G-GRAFT did (Bench 430: −98% tok/s, FAIL vs no-graft baseline — theirs: neuron translation into SmolLM2 "has not worked yet"). Actionable for riir-train as a recipe ROW, not a plan: *before training a skill into a small model, price the graft — if the task digitizes into a table over linearly-readable state, the closed-form overlay is the baseline to beat.* Recorded here; riir-train owners may cite it in the next training-decision gate.

**Workspace sweep (notes + code, 9,539 note files + all `*.rs`; one subagent miss caught at verdict):** nothing ships the COMPOSITION. **CORRECTION (verdict round 1, coordinator spot-check):** the sweep agent's `least.squares|lstsq|normal equation` grep returning zero was WRONG — closed-form least-squares machinery SHIPS in `katgpt-attn-match`: `beta_fitter.rs::fit_beta_nnls` L78–123 (normal equations `(AᵀA)w = Aᵀm`, Cholesky with diagonal jitter on rank deficiency, NNLS refinement warm-started from the clamped LS solution), `value_fitter::fit_cv_least_squares` + `cholesky_decompose` with blocked/unblocked dispatch and ridge (`compact.rs` L336–347), `DEFAULT_CHOLESKY_JITTER` (`lib.rs` L145). The gap the graft fills is therefore NARROWER and precise: the solver exists; **no probe→rule-table→switch→logit pipeline consumes it for capability grafts** — no per-digit hidden-state reads, no mined deciding-input tables, no last-layer probe-driven logit writes. Novelty wording follows: the graft is a new CONSUMER FAMILY for existing fitting machinery (novel-to-workspace), never new numerics. The cousins that SHRINK (must cite, never claim): `npc_brain_graft` (owns "graft" + ProbeSet + authored-overlay-no-training + sidecar manifest + interference gate), FPCG (owns hidden-state probes; read-only by constraint), LoraPair/LoRAHotSwap (owns sidecar-overlay + per-class switch + base-untouched doctrine; weights trained), TokenGate key-bias (owns deterministic overlay + gating + bias writes, riir-infer), PhraseBoost (owns sampling-time lookup→logit-bias writes, GOAT-promoted), SigmoidGateCalibrator (owns closed-form fitted gates), Bench 430 G-GRAFT (the failed trained-router graft-onto-frozen-LM precedent), Research 584's census (Nief ICLR 2026 dynamic weight grafting — delta-subset prior). Helpful precedent: npc_brain_graft's ProbeSet is the authored ancestor of "the smallest set of inputs that decides expected answers"; the miner is its fitted generalization.

## 5. Verdict

**Pinned claim (§1.5 precondition):** *a fitted rule-circuit graft — closed-form digit probes reading hidden state, minimal-deciding-set rule tables mined from a few hundred solved examples, fitted per-class switches, computed logit writes — as a modelless, digest-pinned sidecar overlay adding a deterministic skill to a small model for ≤0.1% added parameters* for **the workspace's inference stack**.

| Gate | Score | Reason |
|---|---|---|
| Q1 no prior art | **NO (strictly)** | Class-level published prior art is dense (ITI + CAST + WISE + DExperts + the arithmetic-training line); the *composition* has no single antecedent. Novel-to-workspace, NOT novel-to-world (the Research 584 standard). |
| Q2 new behavior class | YES (in-stack) | No workspace incumbent can *compute and write* a deterministic answer into a served model's sampling distribution: FPCG is read-only by constraint, npc_brain grafts at mint-time on hand-encoded 8–10-dim observations, LoraPair needs trained weights, PhraseBoost entries are hand-supplied. |

| Q4 force multiplier | YES | Lands on ≥2 existing pillars: LoraPair/hot-swap doctrine + sigmoid gate calibration + FPCG probe family + npc_brain graft lineage + PhraseBoost write seam. |
